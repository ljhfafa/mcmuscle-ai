# 算法、来源与适用边界

## 能量与蛋白质

常用简化 Mifflin–St Jeor：`10×kg + 6.25×cm − 5×age + s`，男性参数s=5、女性参数s=−161。原论文研究的是静息能量消耗，界面中的BMR是常见简称；不是代谢检测。完整参数缺一项即不生成BMR/TDEE，性别不从姓名推测。

原始研究：[Mifflin et al., 1990](https://pubmed.ncbi.nlm.nih.gov/2305711/)。全天活动系数1.2、1.375、1.55、1.725是常见规划假设，不能由每周训练次数直接确认。TDEE与热量目标都应随实际状态调整。

运动人群日蛋白质范围1.4–2.0g/kg，来源：[ISSN position stand, 2017](https://pmc.ncbi.nlm.nih.gov/articles/PMC5477153/)。本工具只使用健康成人的一般范围，不将减脂运动员的特殊高剂量方案推广给所有人。年龄未知时明确标注成人适用前提；未成年人、孕哺期、严重疾病、超出适用年龄、低体重减脂不套用普通公式。

增肌10%盈余、减脂15%缺口、脂肪能量30%、单餐1/3为透明可调整的产品规划默认值，不是上述论文给出的个体处方。缺口最大20%、盈余最大15%；日目标不低于该公式静息能量只是保守产品护栏，不应被解释为临床安全阈值。碳水按剩余能量计算，不能输出负数。

## 搜索与目标函数

确定性深度优先枚举无序商品组合：每项0..max_quantity，总份数<=max_items。默认每项最多2份，总数4，80,000节点。候选按商品ID排序，平分也按ID打破，结果可复现。非负价格/营养允许安全上界剪枝。

硬约束先筛，软分数后排：A按蛋白质降序，再热量偏差、偏好、价格；B把每克蛋白质成本与蛋白缺口、相对热量偏差、脂肪/碳水偏差和偏好组合；C主要最小化相对热量偏差，并惩罚蛋白不足和脂肪超标。公式与权重可直接审阅 `optimizer/engine.py`。这些分数是工程效用函数，不是医学证据。

严格保留缺失值和分母为0的不可计算状态。每100元蛋白质用于比较密度，不鼓励消费100元的餐食。限制每餐总份数，避免以大量重复购买刷蛋白质指标。

官方算价前允许超出原价预算，避免遗漏可能折后可行的组合；算价后重查预算。只对有限候选调用官方接口，不穷举所有券。全局最优声明只可能在明确完整枚举的本地空间成立；输出仍以“限定候选比较”为准。

## 数据边界

官方营养是标准餐品每份值，不是100g值。TOON当前适配嵌套对象、标量表格和JSON包装；不是完整TOON规范实现。字段和声明行/列数不符则拒绝。未知单位不猜测；未知营养商品排除。套餐只有在组件和数量完整明确时才汇总。

官方返回不含完整过敏与交叉接触信息。过敏场景默认拒绝未知餐品；名称标签仅用于偏好，不能用作安全证明。自动流程排除随单购买会员卡才能获得的价格、未选定组件的套餐及未知特制营养。餐品数据库更新时间未提供时如实显示未知。
